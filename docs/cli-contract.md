# Command and file contract

Use Python 3.12 or later and the `satellite-lab` CLI. Exit 0 means success, 2 means argument syntax error, and 1 means controlled input or runtime failure. Every command that writes results requires a new output directory. Existing directories are rejected before work starts.

- `acquire --output NEW_DIR`: the only imagery network operation. Read only the pinned original Sentinel-2B products from 14 February 2020 and 2 August 2020, tile 45RYJ. No arbitrary URL argument, credentials, or paid service. HTTP ranges require matching strong ETags, exact response ranges, pinned asset sizes, and derived-array checksums. Bounds are 64,000,000 payload bytes, 256 requests, and a 600-second acquisition budget; an individual network operation can take up to 20 seconds. This is a stopping bound, not a promised download speed. Save `before.tif`, `after.tif`, and `acquisition.json` only after all scene pixels verify.
- `analyze --before BEFORE.tif --after AFTER.tif --output NEW_DIR`: offline analysis of local north-up projected-metre GeoTIFFs. Six bands are green DN, SWIR DN, SCL, display red, display green, display blue; nodata is 0. Required tags are timezone-aware `acquisition_datetime`, `source_id`, `reflectance_scale`, and `reflectance_offset`. Bounds are 32,000,000 bytes per file, 2,000 pixels per dimension, and 2,000,000 pixels per scene. Display RGB must be finite in [0,255]. The second scene is explicitly aligned to the first grid, with average optical and nearest categorical/display resampling. First acquisition must precede second.
- `demo --output NEW_DIR`: analyze the bundled historical crops with no external network request.
- `serve --directory DIRECTORY --port 8790`: serve only known exported viewer/result filenames on 127.0.0.1. Read-only GET/HEAD; no write API, directory listing, symlink escape, remote bind, or CORS grant. Host must be exactly 127.0.0.1:port or localhost:port (bare host is also valid for port 80). Port 0 requests an OS-selected port for tests. Stop with Control-C.

Outputs are `metrics.json` (schema 1, source/data hashes, exact dates/grid, effective scales/offsets, counts and areas at thresholds −0.1, 0, 0.1, 0.2, 0.3), `change.tif` (fixed threshold 0.00), `footprint.geojson` (WGS84 grid footprint), PNG imagery/classification, little-endian float32 MNDWI arrays compressed with deterministic gzip headers, and a static viewer. `data.json` holds display metadata and result/asset SHA256 hashes. Classification codes are 0 excluded, 1 stable land, 2 persistent candidate water, 3 candidate gain, and 4 candidate loss.

All comparisons use the same both-date valid footprint. SCL 4/5/6 and finite positive optical reflectance are required on both dates; raw DN 0 stays invalid before applying an offset. Water candidates are strictly greater than the selected MNDWI threshold. Counts and their denominators are saved. Areas are projected grid estimates, not independent flood ground truth. Geographic-degree and non-metre input grids are rejected.

A `pinned-historical-study` label requires the fixed array hashes, source IDs, dates, CRS, transform, shape, and scale/offset from the pinned metadata. Other valid inputs are labeled `custom-unverified`, including tag-only scale or offset changes. No calibrated probability or accuracy score is produced.
